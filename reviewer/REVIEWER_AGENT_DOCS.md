# Phase 5: Reviewer Agent Documentation

## Overview

The **Reviewer Agent** is the fourth critical component in the MarginGuard AI multi-agent pipeline. It acts as the quality control and compliance layer, auditing pricing strategy reports generated by the Synthesis Agent against financial guardrails, identity constraints, and structural requirements.

**Owner:** Sam  
**Phase:** 5 of 9  
**Status:** Standalone function (ready for LangGraph integration in Phase 6)

---

## Architecture

### Project Context

MarginGuard AI solves the problem: *"Product managers spend hours manually checking if competitors are undercutting prices, and can't quickly tell if reacting is feasible within margin constraints."*

The solution is a **multi-agent orchestration pipeline** where:
- **Phase 1:** Data + Database (pgvector Postgres setup)
- **Phase 2:** RAG Agent — retrieves internal product/policy data
- **Phase 3:** Research Agent — fetches live competitor pricing via Tavily
- **Phase 4:** Synthesis Agent — generates pricing strategy report
- **Phase 5:** Reviewer Agent ← **This module** — audits the report
- **Phase 6:** LangGraph integration — wires all agents into a workflow graph
- **Phase 7:** FastAPI wrapper — exposes /analyze endpoint
- **Phase 8:** React frontend — UI for querying and viewing results
- **Phase 9:** Demo and iteration

### Workflow Position

```
RAG Agent (Phase 2)
     ↓ rag_output
Synthesis Agent (Phase 4) ← Research Agent (Phase 3)
     ↓ report
Reviewer Agent (Phase 5) ← [THIS MODULE]
     ↓ status + feedback
     ├→ APPROVED: Pass to LangGraph output
     └→ REJECTED: Feedback to Synthesis Agent for retry (max 3 retries)
```

## Function Signature

### `review(report: str, rag_output: dict, research_output: dict) -> dict`

**Purpose:** Validate a pricing strategy report against corporate compliance rules.

**Parameters:**

| Parameter | Type | Description | Example |
|-----------|------|-------------|---------|
| `report` | `str` | Markdown-formatted pricing strategy including a DATA SUMMARY MATRIX | See [Report Structure](#report-structure) |
| `rag_output` | `dict` | Internal product constraints from Phase 2 RAG retrieval | `{"name": "CloudScale Tier-2", "sku": "CS-ENT-02", "our_price": "$80", "margin_floor": "$100"}` |
| `research_output` | `dict` | Live competitor data from Phase 3 research | `{"competitor_name": "ApexCloud v2", "competitor_price_normalized": "$112.50"}` |

**Returns:**

```python
{
    "status": "approved" | "rejected",
    "feedback": None | str  # None if approved; detailed rejection reason if rejected
}
```

---

## Function Implementation

### Core Logic Flow

1. **Prompt Construction:** Build an audit prompt that embeds RAG and research context alongside the report.
2. **LLM Invocation:** Call Grok 2 (xAI) with temperature=0.0 for deterministic output.
3. **Output Parsing:** Parse the LLM's response into one of two formats:
   - `"APPROVED"` → return `{status: "approved", feedback: None}`
   - `"REJECTED: [reasons]"` → extract and return the reasons as feedback
4. **Error Handling:** Catch unexpected LLM formats and mark as rejected.

### Audit Rules (Embedded in Prompt)

The function enforces **three non-negotiable checks:**

#### 1. Financial Guardrail Check
- **What:** Extract `FINAL_RECOMMENDED_PRICE` from the report's DATA SUMMARY MATRIX.
- **Rule:** Must be `>= margin_floor` (from `rag_output`).
- **Violation:** Price below margin floor → **FATAL REJECTION** (prevents unprofitable pricing).
- **Example:** If margin floor is $100 and report recommends $95 → automatic rejection.

#### 2. Identity Alignment Check
- **What:** Validate that product SKUs and competitor brand names in the report match the RAG and research inputs exactly.
- **Rule:** No hallucinations, no name mutations, no SKU mismatches.
- **Violation:** SKU mismatch or competitor name mismatch → **REJECTION** (prevents data corruption).
- **Example:** Report says "CS-ENT-03" but RAG says "CS-ENT-02" → rejection.

#### 3. Structural Completeness Check
- **What:** Ensure the report contains substantive analysis sections.
- **Rule:** Must include "Executive Summary" and "Recommended Action" sections.
- **Violation:** Data-only matrix with no narrative → **REJECTION** (prevents incomplete outputs).
- **Example:** Report has only a matrix with no analysis text → rejection.

## Input & Output Schemas

### `rag_output` (from Phase 2)

```python
{
    "name": str,           # Product name (e.g., "CloudScale Enterprise Tier-2")
    "sku": str,            # Product SKU (e.g., "CS-ENT-02")
    "our_price": str,      # Current internal price (e.g., "$80.00")
    "margin_floor": str    # Minimum acceptable selling price (e.g., "$100.00")
}
```

### `research_output` (from Phase 3)

```python
{
    "competitor_name": str,                    # Competitor brand (e.g., "ApexCloud v2")
    "competitor_price_normalized": str         # Their normalized price (e.g., "$112.50")
    # Additional fields (features_found, sources) are ignored by reviewer
}
```

### Report Structure (from Phase 4)

The report must include:
1. **Markdown sections** (Executive Summary, Market Analysis, Recommended Action, etc.)
2. **DATA SUMMARY MATRIX** (data-only block at the bottom)

Example structure:
```markdown
# Market Position & Pricing Strategy Report

## Executive Summary
[Narrative text]

## Recommended Action
[Narrative text]

### DATA SUMMARY MATRIX
- TARGET_PRODUCT_SKU: CS-ENT-02
- TARGET_PRODUCT_NAME: CloudScale Enterprise Tier-2
- INTERNAL_BASE_COST: $80.00
- INTERNAL_MARGIN_FLOOR: $100.00
- LIVE_COMPETITOR_NAME: ApexCloud v2
- LIVE_COMPETITOR_PRICE_NORMALIZED: $112.50
- FINAL_RECOMMENDED_PRICE: $105.00
- STRATEGIC_ACTION_PLAN_INCLUDED: TRUE
```

### Return Value

```python
# APPROVED case
{
    "status": "approved",
    "feedback": None
}

# REJECTED case
{
    "status": "rejected",
    "feedback": """• CRITICAL FINANCIAL GUARDRAIL VIOLATION DETECTED:
  The extracted FINAL_RECOMMENDED_PRICE of $95.00 is BELOW the mandatory margin floor of $100.00.
  
• ROOT CAUSE:
  Aggressive undercutting strategy violates profitability constraints.
  
• REQUIRED CORRECTION:
  Rewrite recommendation with price >= $100.00."""
}
```

## How to Use (Phase 5: Standalone)

### Setup

1. **Install dependencies:**
   ```bash
   pip install langchain langchain-xai
   ```

2. **Set environment variable:**
   ```bash
   export XAI_API_KEY=your_xai_api_key_here
   ```

3. **Import and call:**
   ```python
   from reviewer_agent import review

   rag = {"name": "CloudScale Tier-2", "sku": "CS-ENT-02", 
          "our_price": "$80", "margin_floor": "$100"}
   research = {"competitor_name": "ApexCloud v2", 
               "competitor_price_normalized": "$112.50"}
   report = "[Markdown report text with DATA SUMMARY MATRIX]"

   result = review(report, rag, research)
   print(result["status"])    # "approved" or "rejected"
   print(result["feedback"])  # None or detailed reasons
   ```

### Running Tests

```bash
cd /path/to/reviewer
python reviewer_agent.py
```

Output will show both test cases with full status and feedback.

### Expected State Schema

When integrated into LangGraph, the state will include:

```python
state = {

    "rag_output": dict,          # From Phase 2

```

### Graph Edges (Phase 6)

```
Synthesis Node
     ↓
Reviewer Node
     ├→ (is_approved == True)  → END / Output
     └→ (is_approved == False && retry_count < 3) → Synthesis (with feedback)
                             && retry_count == 3  → END / Final Rejection
```

## Error Handling

| Scenario | Behavior | Resolution |
|----------|----------|-----------|
| LLM returns unexpected format | Mark as rejected with "Unexpected audit response format" error | Check LLM prompt for clarity; tune temperature or model |
| Missing `FINAL_RECOMMENDED_PRICE` in report | Catches via structural completeness check | Synthesis Agent must include DATA SUMMARY MATRIX |
| SKU mismatch between report and RAG | Triggers identity alignment rejection | Synthesis Agent must not hallucinate SKUs |
| Missing environment variable | Raises `ValueError` at module load | Set `XAI_API_KEY` before importing |

---

## Key Design Decisions

1. **Standalone Function First:** Designed as a pure function (not LangGraph node) so it can be tested in isolation before integration.
2. **Deterministic Temperature:** `temperature=0.0` ensures consistent audit decisions; no random variation in compliance checks.
3. **Three-Layer Audit:** Financial + Identity + Completeness rules provide comprehensive guardrails covering profitability, data integrity, and output quality.
4. **LLM as Judge:** Leverages Grok's reasoning to parse complex markdown and make nuanced compliance decisions, rather than brittle regex parsing.
5. **Detailed Feedback:** Rejection feedback is structured and actionable, helping the Synthesis Agent understand exactly what to fix on retry.
