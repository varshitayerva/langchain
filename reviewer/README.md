## Overview

The Reviewer Agent is the compliance gatekeeper for the MarginGuard AI pipeline. It audits pricing strategy reports generated by the Synthesis Agent, ensuring they comply with:

1. **Financial guardrails** (price >= margin floor)
2. **Identity alignment** (product names and SKUs match exactly)
3. **Structural completeness** (required markdown sections present)

## Integration with Phase 6 (LangGraph)

### Required State Schema

```python
state = {
    "query": str,                      # User's product query
    "rag_output": dict,                # From Phase 2
    "research_output": dict,           # From Phase 3
    "report": str,                     # From Phase 4
    "feedback": Optional[str],         # From Phase 5 (for retries)
    "is_approved": bool,               # From Phase 5
    "retry_count": int,                # Tracks retry attempts
}
```

### Graph Integration

```python
from langgraph.graph import StateGraph
from reviewer_agent import reviewer_node

graph = StateGraph(state_schema)

# Add nodes (once all phases are implemented)
graph.add_node("rag_agent", rag_node)
graph.add_node("research_agent", research_node)
graph.add_node("synthesis_agent", synthesis_node)
graph.add_node("reviewer_agent", reviewer_node)

# Add edges
graph.add_edge("rag_agent", "research_agent")
graph.add_edge("research_agent", "synthesis_agent")
graph.add_edge("synthesis_agent", "reviewer_agent")

# Conditional routing
def route_on_approval(state):
    if not state["is_approved"] and state["retry_count"] < 3:
        return "synthesis_agent"  # Retry
    return "END"  # Done

graph.add_conditional_edges("reviewer_agent", route_on_approval)
```

## Key Design Decisions

1. **Grok 2.0 with temperature=0.0**
   - Ensures deterministic compliance decisions
   - No random variation in audit outcomes

2. **Fast-Fail Guard**
   - Checks for DATA SUMMARY MATRIX before LLM call
   - Saves API costs on malformed reports

3. **Currency Parsing**
   - Supports "$100.00" and 100.00 formats
   - Uses regex for secure extraction

4. **Dual Schema Support**
   - Handles both list (production) and dict (mock) product_data
   - Enables testing without full Postgres setup

5. **JSON Output Enforcement**
   - Forces LLM to output parseable JSON
   - Includes structured error handling

## Audit Criteria

### Financial Guardrail
```
FINAL_RECOMMENDED_PRICE >= margin_floor
```
**Violation:** Automatic rejection with detailed feedback on margin floor breach.

### Identity Alignment
```
SKU matches exactly
Competitor name matches exactly
No hallucinations or data corruption
```
**Violation:** Rejection if any field misaligns.

### Structural Completeness
```
Report contains "## Executive Summary"
Report contains "## Recommended Action"
Report contains "### DATA SUMMARY MATRIX"
```
**Violation:** Rejection if any section missing.

## Error Handling

| Scenario | Behavior |
|----------|----------|
| Missing DATA SUMMARY MATRIX | Fast-fail rejection (no LLM call) |
| LLM JSON parse error | Caught, logged, return error feedback |
| Invalid currency format | Default to 0.0; continue audit |
| Empty product_data list | Return error feedback |
| Missing margin_floor | Default to "Unknown"; continue audit |

## Troubleshooting

**Error: "XAI_API_KEY environment variable is not set"**
- Solution: Add `XAI_API_KEY=your-key` to .env

**Error: "connection to server at localhost:5432 failed"**
- Solution: This is expected if Postgres not set up. Use mock data for testing.

**Error: "LLM JSON PARSE ERROR"**
- Solution: LLM didn't return valid JSON. Check prompt formatting in code.

See [QUICKSTART_TESTING.md](./QUICKSTART_TESTING.md) for more troubleshooting.
