2. KEY ARCHITECTURE CHANGES
═══════════════════════════════════════════════════════════════════════════════

RETRY LOOP:
  ✅ If reviewer rejects → Synthesis regenerates with feedback
  ✅ Max 3 attempts total (0-based: retries 1, 2, 3)
  ✅ Self-correction: Each retry includes reviewer feedback
  ✅ Loop stops on: approval OR max retries reached

HITL ESCALATION:
  ✅ If retry_count reaches 3 AND still rejected → Escalate to human review
  ✅ NOT a hard exit (sys.exit) anymore
  ✅ Instead: Route to human_review node
  ✅ Graph pauses BEFORE human_review (interrupt_before)
  ✅ State checkpointed to MemorySaver

CHECKPOINT MANAGEMENT:
  ✅ thread_id = execution_id (same identifier)
  ✅ MemorySaver stores paused state
  ✅ /resume endpoint fetches from checkpoint
  ✅ Resumes from exact pause point
  ✅ Human decision injected into state
  ✅ Graph continues from human_review node

4. CONDITIONAL ROUTING LOGIC
═══════════════════════════════════════════════════════════════════════════════

OLD LOGIC:
  if approved → END
  elif retry_count < 3 → Back to synthesis
  else → END (hard exit)

NEW LOGIC:
  if approved → END
  elif retry_count < 3 → Back to synthesis (with feedback)
  else → human_review (pause for human)

ROUTING TARGETS:
  "synthesis"    ← Retry (feedback included)
  "human_review" ← HITL escalation (NEW)
  "end"          ← Complete

7. RETRY LOOP EXAMPLE
═══════════════════════════════════════════════════════════════════════════════

Attempt 1:
  SYNTHESIS: Generate report
  REVIEWER: Check compliance
  RESULT: ❌ REJECTED - Price below margin floor
  ACTION: Increment retry_count=1, loop back to synthesis

Attempt 2 (with feedback):
  SYNTHESIS: Regenerate report (using reviewer feedback)
  REVIEWER: Check compliance
  RESULT: ❌ REJECTED - Still non-compliant
  ACTION: Increment retry_count=2, loop back to synthesis

Attempt 3 (with feedback):
  SYNTHESIS: Regenerate report (using updated feedback)
  REVIEWER: Check compliance
  RESULT: ❌ REJECTED - Still non-compliant
  ACTION: Increment retry_count=3, escalate to HITL

HITL Escalation:
  ROUTE: Route to human_review node
  PAUSE: Graph pauses BEFORE executing human_review
  STATE: Checkpointed to MemorySaver
  WAIT: Awaiting /resume endpoint call

  Client calls: POST /resume with override decision

  RESUME: Graph resumes from checkpoint
  INJECT: human_decision added to state
  EXECUTE: human_review node runs with decision
  END: Graph completes with human override applied

FASTAPI INTEGRATION:
─────────────────────────────────────────────────────────────────────

from fastapi import FastAPI
from api.main_refactored import app

# Run with: uvicorn api.main_refactored:app --reload

# Client code (JavaScript):
const res = await fetch('http://localhost:8000/analyze', {
  method: 'POST',
  body: JSON.stringify({query: 'CloudScale Enterprise'})
});
const {execution_id} = await res.json();

// Poll status
const status = await fetch(`/status/${execution_id}`).then(r => r.json());

if (status.status === 'paused_for_human_review') {
  // Show UI for human to approve/reject
  const resume = await fetch(`/resume/${execution_id}`, {
    method: 'POST',
    body: JSON.stringify({
      override_decision: 'override_approve',
      notes: 'Approved by management'
    })
  }).then(r => r.json());

  console.log(f"Final decision: {resume.final_decision}");
}
